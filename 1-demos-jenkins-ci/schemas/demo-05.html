Démo 5 — Configuration System et agent SSH

Slides : 23, 43, 46 · Durée : 20 min · Prérequis : démo 4, conteneur linux-1 démarré (démo 0)

Pourquoi cette démo

Jusqu'ici, les builds tournent sur le controller. La slide 23 pose la règle inverse : le controller orchestre, les agents exécutent, et le node built-in garde 0 executor. Cette démo met en place cette architecture avec un agent SSH, le mode de connexion le plus courant sous Linux (slide 46), et règle au passage les paramètres globaux de la page System (slide 43).

Ce qu'elle montre

Un credential de type clé SSH à portée System, la création d'un node permanent avec ses labels, le log de connexion où le controller copie agent.jar, un job qui s'exécute sur linux-1 grâce à son label, et ce qui arrive à un job sans label une fois le controller passé à 0 executor.

À retenir

À retenir. Controller à 0 executor + agents porteurs de labels = le build ne touche jamais JENKINS_HOME, et la capacité se gère en ajoutant des agents (slide 23). Tous les Jenkinsfiles du kit demandent agent { label 'linux' }.
