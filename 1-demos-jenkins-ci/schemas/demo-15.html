Démo 15 — Analyse qualité avec SonarQube

Slides : 71 à 73 · Durée : 25 min · Prérequis : démo 14

Pourquoi cette démo

Les tests disent si le code fait ce qu'on attend ; l'analyse statique dit s'il est maintenable et sûr. La slide 72 enchaîne mvn verify, mvn sonar:sonar et waitForQualityGate : SonarQube rend son verdict par webhook et Jenkins arrête le pipeline si la Quality Gate est rouge. Le réglage croise trois écrans (SonarQube, credentials, System), d'où l'intérêt de le dérouler une fois en entier.

Ce qu'elle montre

La génération d'un token SonarQube, le webhook vers Jenkins, la déclaration du serveur dans Jenkins, une analyse dont le lien s'affiche sur le build, puis une Quality Gate durcie qui fait échouer le pipeline. En bonus, l'onglet Warnings NG (slide 73).

À retenir

Point clé. Sans le webhook de l'étape 5, waitForQualityGate attend jusqu'au timeout (10 minutes) : c'est la première chose à vérifier quand ce stage ne se termine pas. La livraison du webhook se lit dans SonarQube (Administration → Webhooks, colonne Last delivery).
