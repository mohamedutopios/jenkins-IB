Démo 0 — Démarrer l'environnement

Slides : 40 · Durée : 10 min · Prérequis : Docker Desktop (ou Docker Engine + Compose v2), 8 Go de RAM alloués à Docker, accès Internet (images, plugins, dépendances Maven)

Pourquoi cette démo

Toutes les démos utilisent le même environnement, décrit dans un seul fichier docker-compose.yml. Le préparer une fois évite de mélanger l'installation de l'outillage et l'apprentissage de Jenkins. On reprend ici la proposition de la slide 40 (Jenkins en conteneur avec un volume pour JENKINS_HOME), complétée par un serveur Git local : sans lui, il faudrait un compte GitHub et un tunnel (ngrok, smee.io) pour que les webhooks atteignent le Jenkins du poste.

Ce qu'elle montre

Un Jenkins « nu » (image officielle, aucun plugin préinstallé) qui attend son assistant de premier démarrage, un agent SSH prêt à recevoir des builds, et le dépôt Git privé formation/library-api qui contient le projet du fil rouge et ses Jenkinsfiles.

  3. Démarragedocker compose up -d --build : 4 services running

À retenir

Point clé. docker compose down arrête la stack sans rien perdre : JENKINS_HOME, le dépôt Gitea et le cache Maven sont dans des volumes nommés. Seul docker compose down -v efface tout (utile pour rejouer la démo 1 depuis zéro).
